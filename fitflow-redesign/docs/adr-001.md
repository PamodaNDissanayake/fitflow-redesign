# ADR 001 FitFlow Technology Stack

## Status

Proposed for implementation.

## Date

29 September 2026

## Author

Dissanayake D M P N B  
IT23846654

## Context

FitFlow requires personalized workouts, private community features,
faster nutrition logging, progress tracking and offline access.

The solution must support iOS, Android and web.

The case study favors React Native, Node.js/Express, Firebase
and TensorFlow Lite. Lab 04 also identifies improvements needed
in labels, AI explanations and visual clarity.

## Decision

Use:

- React Native and TypeScript for mobile.
- React Native Web for compatible browser interfaces.
- Node.js and Express for the main API.
- Cloud Firestore for operational records.
- Firebase Authentication for identity.
- Python and FastAPI for the private AI service.
- LiteRT and ML Kit for suitable mobile models.
- Redis when shared caching or counters are required.
- Private object storage for consented image uploads.

## Alternatives Considered

- Flutter for shared mobile and web UI.
- Kotlin Multiplatform for a team with native development skills.
- SwiftUI with separate Android and web clients.
- NestJS for a more structured main backend.
- PostgreSQL for relational data and reporting.
- Cognito, Auth0 and Supabase Auth for identity.

## Benefits

- Aligns with the case study.
- Supports shared frontend and backend TypeScript skills.
- Provides managed identity and real-time data updates.
- Allows AI services to scale independently.

## Trade-offs

- Firebase creates provider-specific dependencies.
- Database reads and listeners need cost monitoring.
- Web and native integrations require separate testing.
- Python adds another backend language.
- A food model and nutrient data source remain dependencies.

## Review Triggers

Review this decision if:

- Actual team skills differ from the scoring assumptions.
- Device performance is inadequate.
- Database or inference costs become excessive.
- Complex relational queries become essential.
- Regulatory requirements cannot be met by the selected services.

## Validation

Before release, test authorization, offline synchronization,
AI fallback behavior, accessibility and the Lab 04 usability tasks.
